TLDR: The pipeline works end-to-end, but several issues can cause missing data or unreliable results.

* 50 selected bets were never graded, making the reported NHL results incomplete.
* Prediction files are silently overwritten when several scraper snapshots contain the same game date.
* Integer-total EV and Kelly are calculated incorrectly because push probability is removed.
* The games schedule is built from sportsbook odds, so games without odds can disappear.
* FanDuel odds are incorrectly labeled as DraftKings throughout the pipeline.
* The “juice” stage changes model probabilities instead of simply removing sportsbook vig.
* Some juice adjustments are extreme, including -0.7231.
* Invalid puck-line calculations can be capped at 1.01, creating nearly 99% implied probability.
* Bad or incomplete rows can continue downstream with blank calculations.
* Some scripts record errors but still let the workflow finish successfully.
* Final-score and reporting workflows can succeed without producing current outputs.
* Separate workflows do not enforce the required execution order.
* Multiple simultaneous workflows could overwrite files or create git push conflicts.
* Both opposing sides of moneyline or puck-line markets can be selected.
* Puck-line selections are heavily restricted to expensive odds between -999 and -200.
* Total parsing may select an alternate line instead of the primary sportsbook total.
* The prediction scraper depends on fixed webpage column counts and can break when the page changes.
* The full season—211 dates and 1,393 games—is rebuilt repeatedly.
* Hundreds of empty selection files generate meaningless grading errors.
* Odds snapshots do not preserve a usable pull timestamp on downstream betting rows.
* There are no automated tests for probabilities, EV, Kelly, pushes, selection or grading.
* NHL workflows are currently inside .github/workflows/nhl_offseason, so GitHub Actions will not recognize them until moved directly under .github/workflows.
